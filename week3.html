Week 3: Application Selection for Performance Testing

Select applications representing different workload types for performance evaluation. .

Application selection Matrix.


Workload type Selection Application justification
CPU intensive Sysbench (CPU mode) This is ideal for testing thermal limits and scheduler performance, because it forces the CPU to run at 100% utilisation by calculating prime numbers.
RAM intensiveStress-ngStress-ng effectively simulating a memory leak or a heavy database operation.
I/O intensive Sysbench (FileIO mode) We reuse sysbench here because its "FileIO" mode simulates random read/write operations.
Network intensive iPerf3 iperf3 is the standard tool for measuring active bandwidth.
Server Application Nginx (Web Server) Nginx is a high-performance web server. It represents a real-world "Server Application" workload. Nginx tests how the system handles concurrent connections and file serving.


Installation Documentation.


workstation VM:~
workstation01:~$ ssh ash@192.168.56.10
workstation01:~$ sudo apt update
workstation01:~$ sudo apt install sysbench stress-ng iperf3 nginx -y
workstation01:~$ sysbench --version
workstation01:~$ stress-ng --version
workstation01:~$ iperf3 --version
workstation01:~$ sudo systemctl status nginx

Expected Resource Profiles.


Application Resource target Expected resource profile
Sysbench (CPU) CPU cores 100% on all assigned cores.
Stress-ng RAM RAM usage will fill up to the limit we set (e.g. 90%).
Sysbench (FileIO) Disk I/O CPU usage might be low, but "Load Average" will be high.
iPerf3 Network Card Network traffic on enp0s8 will spike to near 1Gbps (or higher depending on virtualization). CPU usage may rise slightly to process the network packets.
Nginx Mixed Low idle usage. Moderate CPU and RAM spikes during requests. Logs will be generated in /var/log/nginx/.

Monitoring Strategy explaining measurement.


For the controller I'll open one terminal on the Workstation SSH'd into the Server to run the stress command. While for the Monitor I'll open a second terminal on the Workstation SSH'd into the Server to watch the metrics.


Workload Primary monitoring tool Metric to moitor.
General / CPU Sysbench (CPU mode) Look at the colored bars at the top. Green = User processes. Red = Kernel processes. Watch for the bars hitting 100%.
Memoryhtop or free -hIn htop, watch the Mem bar. Watch the Swp bar to see if it spills over to disk.
Disk I/O vmstat 1 Run vmstat 1. Watch the wa column (Wait). If this number is high, your disk is the bottleneck.
Network nload or ip -s link (Optional install: sudo apt install nload). This shows a real-time graph of incoming/outgoing traffic speed.
